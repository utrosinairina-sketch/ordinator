# Проверка исходников и исправления

**Основа:** `ordinator_mobile_app_v7_calendar_grid.zip`. Отдельно загруженный `index.html` отличается по структуре и возможностям; он **не объединялся** с архивной версией автоматически. Старое содержимое `ord_v3` сохранено совместимым с новой реализацией.

## Найденные проблемы в оригинале

| Приоритет | Проблема | Что изменено |
| --- | --- | --- |
| Высокий | Поля карточки и осмотра терялись при переключении вкладки до нажатия «Сохранить». | Автосохранение каждого изменения; черновики отдельных форм сохраняются также при переходах. |
| Высокий | `JSON.parse(localStorage...)` без `try/catch` мог полностью остановить приложение после повреждения данных. | Проверка формата; при ошибке запись блокируется, исходный JSON можно скачать отдельно. |
| Высокий | Данные можно потерять при очистке браузера, смене устройства/домена. В приложении не было резервного копирования. | Добавлены экспорт и импорт JSON с подтверждением замены. |
| Средний | `new Date().toISOString().slice(0,10)` возвращает дату по UTC, которая иногда не совпадает с местным днём. | Используется местная дата. |
| Средний | `Date.now()` как единственный идентификатор может дать коллизию при быстрых действиях. | `crypto.randomUUID()` с резервной генерацией. |
| Средний | Удаление пациента оставляло его задачи и события без корректной привязки. | Связанные задачи и события удаляются с предупреждением. |
| Средний | График использовал `parseFloat`, например часть текстовых или составных значений могла приниматься за число. | Числовой парсер строже; единицы не смешиваются. |
| Средний | Один HTML с разметкой, данными и десятками обработчиков сложен для безопасных доработок. | Выделены CSS, справочники, хранилище и логика интерфейса. |
| Средний | Inline `onclick` усложнял сопровождение и был потенциально опасен при неконтролируемых атрибутах ID. | Переведено на `data-action` и единый обработчик, текст экранируется. |
| Средний | Service Worker кэшировал произвольные запросы и мог показывать устаревшие файлы. | Кэш ограничен локальными файлами приложения, версия кэша обновлена. |
| Низкий | Нельзя было удалить отдельные задачи/события; обход принимал запись полностью пустой. | Кнопки удаления, проверки числовых полей и непустого обхода. |

## Проверено автоматически в браузерном окружении

- Создание/редактирование карточки и переключение вкладок без потери полей.
- Черновик обхода, сохранение обхода и просмотр таблицы динамики.
- Сохранение лабораторного результата, просмотр истории и графика.
- Создание/выполнение задач, добавление события и календарь.
- Чтение записи формата прежней версии.
- Некорректный JSON в `ord_v3` и защита от автоматического затирания.
- Импорт резервной копии JSON.
- Каскадное удаление пациента и связанных записей.
- Валидация диапазона SpO₂.
- Отсутствие ошибок JavaScript в выполненных сценариях.

**Ограничение проверки:** тесты выполнены в локальной браузерной среде с подставленными статическими ресурсами. Публикация в конкретном GitHub-репозитории и работа с реальными устройствами не проверялись — после загрузки необходимо пройти список проверки из `README.md`.

## Вопросы, которые нельзя считать решёнными только рефакторингом

- Нет шифрования, разграничения доступа, серверного резервирования и юридически значимого журнала действий.
- Сайт **не предназначен для клинического применения и хранения реальных данных пациентов**.
- График — иллюстрация записей, а не медицинский аналитический инструмент.
- Тот же origin (`https://user.github.io`) может использоваться несколькими разными GitHub Pages-проектами; `localStorage` общий для всех путей на origin. Поэтому не запускайте второй независимый «Ординатор» под тем же ключом `ord_v3`.
