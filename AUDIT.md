# Технический отчёт v9

## Основание

Объединены четыре блока ТЗ: «Динамика + инструментальные исследования», «Лаборатория», «Обход», «Терапия» (из присланного Markdown). Основа: ZIP версии v8 с сохранением цветовой схемы и компонента карточки, совместимость данных v7/v8.

## Изменённые файлы

- `index.html`: навигация и вход для локальных таблиц.
- `styles.css`: компактные раскрывающиеся формы, недельная таблица с фиксированной датой.
- `js/app.js`: клинические формы, действия, история терапии и привязка данных.
- `js/storage.js`: добавочные массивы `studies`, `examHistory`, `therapy`, `therapyHistory`, `therapySnapshots`; справочники `labRefs`, `drugCatalog`; чтение старого JSON.
- `js/clinical.js` (новый): спецификации исследований/лекарств, проверка чисел и CKD-EPI 2021.
- `js/dynamics.js` (новый): производные наборы измерений и графики.
- `js/excel.js` (новый): декодирование нешифрованных XLSX/CSV в браузере.
- `sw.js`: обновлённый кэш файлов.
- `README.md`, `CHANGELOG.md`, `AUDIT.md`: инструкция и ограничения.

## Модель данных

Сохранены корневые массивы пациентов, задач и событий, старые `patient.rounds`, `patient.results`, `patient.exam`. Новый `patient.studies[]` содержит одну запись на исследование, `patient.examHistory[]` — фиксированные по дате снимки. В `patient.results[]` новые лабораторные записи содержат `metricId`, `numericValue`, `unit`, `specimen`, `method`, `referenceSnapshot`, но старые `name/value/previous` не удаляются. `patient.therapy[]` хранит актуальные назначения, `patient.therapyHistory[]` — события с `before`/`after`, `patient.therapySnapshots[]` — подтверждённые вручную наборы из файлов для сравнения. Динамика строится из этих данных на лету.

## Принципы безопасного поведения

- Нет автоматического заполнения пропущенных измерений нулями.
- Новые числовые лабораторные результаты хранятся отдельно от единиц измерения.
- Разные единицы, биоматериалы и методы не смешиваются в одну лабораторную серию.
- Старые значения не удаляются при перемещении разделов: неопределённые показатели вынесены в блоки совместимости.
- Реальных лабораторных референсов в коде нет: только врач задаёт метод-специфические значения; измерения сохраняют собственный снимок настроек на дату.
- Для рСКФ нужна подтверждённая IDMS-стандартизация и данные пациента. Формула из NIDDK: https://www.niddk.nih.gov/research-funding/research-programs/kidney-clinical-research-epidemiology/laboratory/glomerular-filtration-rate-equations/adults
- Терапевтические предупреждения только о полноте форм и возможных точных дублях. Клиническая система проверки взаимодействий отсутствует.

## Тесты

1. Автоматическая проверка синтаксиса `node --check` для модулей.
2. Chromium: создание пациента, запись и сохранение обхода, лабораторного результата, ЭКГ, назначения; просмотр «Динамики».
3. Chromium: повторная загрузка из сохранённого JSON локального хранилища в новом документе.
4. Chromium: старая карточка v7 со старыми обходами и результатами — доступна и редактируется; изменение лабораторного результата не дублирует запись.
5. Chromium: журнал назначения содержит прежнюю и новую дозу; сохранение осмотра на одну дату дважды не создаёт дубля.
6. Chromium: старые инструментальные заключения остаются доступны; старые задачи не исчезают.
7. Chromium: загружен тестовый `.xlsx` c несколькими строками, отображено сопоставление колонок, создан импортированный набор для сравнения.
8. В перечисленных сценариях JavaScript `pageerror` не обнаружено.

## Ограничения и что не тестировалось

- Проверки выполнялись в Chromium с инъекцией тестового DOM/памяти из-за ограничений сетевой навигации окружения; **не является полным end-to-end тестом развернутого GitHub Pages**.
- Не проведена реальная ручная проверка Android/GitHub Pages, браузеров Safari/Firefox и старых `.xls`.
- Нет защищённой МИС / серверной синхронизации, валидированной базы медицинских справочников, реальных клинических порогов, проверок доз и лекарственных взаимодействий.
- Несопоставленные лабораторные записи без единиц остаются в старом формате, без самовольного преобразования.
- Сравнение лекарств без уверенного МНН/формы/пути помечается для проверки, а не автоматически признаётся точным совпадением.
