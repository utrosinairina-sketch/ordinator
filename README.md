# Ординатор — версия 8, статический сайт/PWA

Это **демонстрационный прототип** для условных данных. Он не предназначен для ведения реальной медицинской документации или хранения персональных данных пациентов. Все данные остаются в `localStorage` конкретного браузера и **не шифруются**. Нет авторизации, сервера, синхронизации между устройствами, контроля доступа, аудита, аттестации или резервного копирования «в облаке».

## Как обновить сайт на GitHub Pages — без программирования

1. **Сначала** откройте на старом сайте вкладку **«Пациенты» → «Скачать копию JSON»**. Сохраните файл в защищённое место.
2. Распакуйте полученный ZIP на компьютере. **В самом репозитории должен быть `index.html` в корне**, рядом с `styles.css`, `sw.js`, `manifest.webmanifest` и папкой `js`.
3. На GitHub откройте нужный репозиторий. Замените файлы через **Add file → Upload files**, включая каталог `js` со всеми файлами. Не загружайте один ZIP вместо его содержимого: GitHub Pages не распакует его автоматически. Если интерфейс загрузки не принимает папку, перетащите её вместе с файлами или загрузите файлы внутри `js` отдельно.
4. Нажмите **Commit changes**. В **Settings → Pages** проверьте **Deploy from a branch**, ветка **main**, папка **/(root)** (если это исходная настройка проекта).
5. Дождитесь завершения GitHub Actions/Pages deployment, обновите сайт. Если прежняя установленная PWA всё ещё показывает старую версию, закройте её полностью и откройте заново. При необходимости проверьте в обычной вкладке браузера, что новая версия доступна.
6. Старые данные автоматически читаются из прежнего ключа `ord_v3` **в том же браузере и по тому же адресу сайта**. Если данные не видны (другой браузер, адрес репозитория или телефон), воспользуйтесь **«Восстановить из JSON»**.

**Важно:** `localStorage` привязан к протоколу, домену и порту (origin), а **не** к папке репозитория. Переход на другой домен потребует переноса через JSON; на том же `username.github.io` два проекта могут видеть один и тот же ключ `ord_v3`. Рекомендуется не менять адрес сайта и не разворачивать несколько независимых «Ординаторов» на одном origin. Обновление кода в GitHub обычно не стирает `localStorage`, но очистка данных сайта или приватный режим — могут.

## Что лежит в файлах

| Файл | Назначение |
| --- | --- |
| `index.html` | Оболочка сайта, меню и подключение модулей |
| `styles.css` | Внешний вид, мобильная адаптация |
| `js/catalog.js` | **Список систем, анализов и полей осмотра/обхода.** Новые показатели удобнее добавлять здесь |
| `js/storage.js` | Сохранение, чтение старых записей, формат JSON, проверки |
| `js/app.js` | Интерфейс, экраны, действия пользователя и графики |
| `sw.js` | PWA: офлайн-файлы и кэш приложения |
| `manifest.webmanifest` | Название и оформление установленного приложения |

**Никакие npm, React, Vite, Node.js и сборка не нужны для публикации.** Это обычный сайт на HTML/CSS/JavaScript. Для проверки на компьютере используйте любой локальный HTTP-сервер; открывать `index.html` двойным щелчком через `file://` недостаточно, так как браузеры блокируют импорт JS-модулей с файловой системы.

## Добавление функций через ChatGPT

Отправляйте не один `index.html`, а **все файлы проекта**. Сначала объясните задачу, затем попросите вернуть **полное содержимое только изменённых файлов и их пути**, без замены прочих файлов. Перед загрузкой нового кода сделайте JSON-копию на старом сайте, затем проверьте существующие функции.

Для добавления новой лабораторной позиции чаще всего достаточно добавить её в нужный массив `labBySystem` внутри `js/catalog.js`. Для новой вкладки необходимо изменить `js/app.js`, а для нового оформления — `styles.css`. Не переименовывайте имеющиеся поля (`exam`, `rounds`, `results`, `tasks`, `events`) и ключ `ord_v3` без миграции.

При изменении ресурсов приложения также меняйте строку `VERSION` в `sw.js`, чтобы установленная PWA получила новые версии файлов. Сервис-воркер кэширует только файлы сайта, а не записи пациентов.

## Важные ограничения

- Данные локальны для браузера и **не синхронизируются** с другим устройством.
- Автосохранение выполняется при вводе (с небольшой задержкой) и немедленно при смене экрана/скрытии вкладки. Кнопка «Сохранить» также доступна.
- Удаление пациента удаляет также связанные с ним задачи и события; показывается подтверждение.
- **Импорт JSON заменяет все текущие данные.** Перед импортом скачайте текущую копию.
- Если браузер повредил локальные данные, приложение **не перезапишет** содержимое `ord_v3` автоматически; будет предложено скачать исходное содержимое для восстановления.
- В двух одновременно открытых вкладках одна из них может сохранить старую копию; при обнаружении внешнего изменения запись блокируется. Работайте с одной вкладкой.
- Графики показывают только числовые значения; разные единицы измерения не объединяются. Не использовать их для клинических решений.

## Быстрая проверка перед публикацией

1. Добавить пациента → заполнить карточку → перейти на другую вкладку → убедиться, что поля сохранились.
2. Добавить обход и результаты исследования, проверить их в истории и графиках.
3. Добавить задачу, отметить её выполненной, добавить и удалить событие в календаре.
4. Сохранить JSON, восстановить его в чистом браузере, проверить совпадение количества записей.
5. Проверить сайт на телефоне и в режиме PWA после обновления.
