# Ординатор v9 — статическое приложение без сборки

## Как проверить до публикации (VS Code)

1. **Сначала сохраните копию данных**, если используете рабочую старую версию: откройте сайт на прежнем адресе, перейдите в **Пациенты → Скачать копию JSON**. Рекомендуется также сохранить прежний ZIP.
2. Распакуйте ZIP так, чтобы `index.html`, `styles.css`, `sw.js`, `manifest.webmanifest` и папка `js` оказались рядом.
3. В VS Code откройте папку проекта (**File → Open Folder**), установите расширение **Live Server**.
4. В `index.html` выберите **Open with Live Server**. Откроется `http://127.0.0.1:5500/` (порт может отличаться).
5. Введите **только вымышленные данные**. Откройте F12 → Toggle device toolbar / Ctrl+Shift+M для проверки телефона.
6. Данные `localStorage` привязаны к адресу **схема + домен + порт**. Данные с настоящего сайта на GitHub Pages **не появятся** на `localhost` автоматически. Тестовую копию можно перенести JSON-экспортом и восстановлением.
7. После проверки разместите **распакованное содержимое** ZIP в корне репозитория GitHub Pages. Сам ZIP загружать как единственный файл нельзя.

При обновлении уже опубликованной версии рекомендуем сначала сделать бэкап, затем загрузить все изменённые файлы одним коммитом. PWA может открыть ранее кэшированную версию при отсутствии связи; при первом доступе в интернет откройте сайт повторно. Если вкладка сообщает о конфликте данных с другой вкладкой — сделайте экспорт и перезагрузите.

## Структура

- `index.html` — каркас страницы, нижняя навигация.
- `styles.css` — оформление на смартфоне и десктопе.
- `js/app.js` — интерфейс и обработчики событий, не содержит загрузок внешних библиотек.
- `js/catalog.js` — прежние справочники осмотра и обхода, в том числе исходные варианты старых исследований.
- `js/clinical.js` — новые лабораторные/инструментальные/лекарственные справочники и CKD-EPI 2021.
- `js/dynamics.js` — единое получение измерений **непосредственно из сохранённых записей**, графики фактических точек.
- `js/excel.js` — локальный парсер простых `.xlsx` и `.csv` без сервера.
- `js/storage.js` — загрузка, проверка и резервное копирование `localStorage`.
- `sw.js`, `manifest.webmanifest` — офлайн/PWA.

**Нет React, Node.js, npm, сборщика, обязательных CDN или серверной базы данных.** Достаточно любого статического HTTP(S)-сервера.

## Где находятся функции

**Пациенты → Открыть → Обход / Осмотр по системам / Лаборатория / Инструментальные / Терапия**.

- **Обход** — ежедневное измерение (обычное сохранение обновляет основную запись на дату), отдельные дополнительные измерения с временем, недельный обзор с фиксированной датой, редактирование и удаление старых записей.
- **Осмотр** — прежние редактируемые поля плюс кнопка «Сохранить осмотр на дату», формирующая датированные снимки для динамики. Ранее введённые текущие данные не удаляются.
- **Лаборатория** — 9 раскрывающихся групп, числовые значения с датой/временем, единицами и биоматериалом, предыдущий и результаты выбранной даты, история и редактирование. Референсы задаются отдельно по показателю/методу/биоматериалу и, при необходимости, полу. Пустые референсы не оцениваются. Старые неоднозначные строки остаются в блоке «Другие и старые».
- **рСКФ** — расчёт по CKD-EPI 2021 (взрослые). Требуются дата рождения, пол в используемой формуле, положительный креатинин сыворотки в мкмоль/л **и явное подтверждение** стандартизации по IDMS. Не является диагнозом; использует `88.4 мкмоль/л` на `1 мг/дл`. Расчёт хранится производным, исходный креатинин остаётся самостоятельной записью. Источник: https://www.niddk.nih.gov/research-funding/research-programs/kidney-clinical-research-epidemiology/laboratory/glomerular-filtration-rate-equations/adults
- **Инструментальные** — структурированные формы ЭКГ, ЭхоКГ, Холтера, УЗИ перикарда, УЗИ плевры, рентгенографии, КТ, дренажей; ЖКТ/мочевыделительная система и старые свободные записи доступны отдельно. Для каждого дренажа задайте самостоятельное обозначение и период измерения.
- **Динамика** — выбор пациента, одной из 4 групп, показателя и просмотр фактических дат/точек. Отсутствующие измерения не достраиваются; результаты в разных единицах и методах строятся раздельно.
- **Терапия** — назначения по группам, ручное редактирование и журнал событий (до/после), отмена, окончание курса, возобновление, сравнение разных дат и импортированных наборов. `.xlsx`/`.csv` загружаются локально: предварительный просмотр листов и сопоставление столбцов, подтверждение; набор для сравнения **не перезаписывает** актуальные назначения. Поддерживается импорт пользовательского справочника лекарств.
- **Календарь и Задачи** — прежние функции сохранены.

## Какие ограничения сохраняются

1. **Это не защищённая МИС:** `localStorage` не шифруется, нет учётных записей, разграничения доступа, сервера, электронных подписей, медицинского аудита и синхронизации. Настоящие идентифицирующие клинические данные сюда вводить нельзя.
2. Нет проверенной базы лекарственных взаимодействий, дозирования при ХБП, противопоказаний, справочника ГРЛС, импортирования с проверкой официальной инструкции. Предупреждения ограничены **отсутствующими полями и точными возможными дублями**; ни отсутствие предупреждений, ни референс не означают отсутствия клинического риска.
3. Исходные **референсные диапазоны не установлены**. Пользователь настраивает их для своего метода; приложение использует их только при совпадении метода и биоматериала и указанного ограничения по полу. Старые результаты с неточными единицами не пересчитываются автоматически.
4. Импорт работает для **обычных незашифрованных XLSX** и CSV (включая типичные UTF-8/Windows-1251). `.xls`, XLSX с паролем, сложными формулами без рассчитанных значений, экзотические файлы и изображения таблиц могут не читаться. Загруженные наборы предназначены для сравнения и ручного подтверждения, а не для автоматической смены назначений.
5. **Внутренняя история изменений** в `localStorage` не является неизменяемым журналом: её можно удалить или подменить из браузера. Сохраняйте независимые резервные копии в защищённом месте.
6. Существовавший в v7/v8 осмотр по системам хранит только последнее значение: старые незафиксированные осмотры невозможно восстановить задним числом. Для новых сохранений предусмотрена кнопка датированного снимка.
7. Функциональные тесты проведены в Chromium с симуляцией локального хранилища. Для реальной публикации обязательны ручные проверки на адресе GitHub Pages и телефоне врача.

## Сохранность старых данных

Сохранён ключ `ord_v3` и поддержка старых записей из v7/v8: `patients`, `rounds`, `exam`, `results`, `tasks`, `events`, `drafts`. Новые поля добавляются к пациенту без стирания старых. Файл резервной копии **не содержит шифрования** и требует такого же осторожного обращения, как данные внутри браузера.

В отличие от прежнего раздела «История результатов», не удаляются сами сохранённые результаты — изменена только точка доступа к ним.
